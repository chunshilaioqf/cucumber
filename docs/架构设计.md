# 黄瓜（cucumber）架构设计文档

**版本**：v1.0 · 对应软件版本 0.1.0
**框架基线**：windui 0.30.0（已在 Linux/X11 完成编译与 Xvfb 冒烟验证）
**需求基线**：《跨平台进程（服务）管理工具需求分析文档》v1.1

本文档记录已实测验证后的技术决策。与需求文档的建议有出入处，均在「ADR」小节给出理由。

---

## 1. 系统概览

黄瓜是一款跨平台（Windows / macOS / Linux）本地进程与服务统一管理工具：

- **GUI**：windui 构建的本地窗口（仪表盘 / 进程 / 所有服务 / 日志 / 对外接口 / 使用说明 / 帮助）。
- **本地 API**：HTTP + WebSocket（axum，仅绑定 127.0.0.1，本地令牌认证）。
- **MCP**：JSON-RPC 2.0 子集，stdio 与 HTTP 两种传输，供 AI Agent 调用。
- **Skill**：内置 `SKILL.md`，一键安装到 AI 宿主目录。

```
┌────────────────────────── UI 线程（windui 事件循环） ──────────────────────────┐
│  menu_bar + tabs 页面路由     Signal<T> 状态     on_interval(3s) 读快照写信号   │
└──────────▲──────────────────────────────┬──────────────────────────────────┘
           │ App::channel（消息→UI）        │ 调用 core 方法（spawn 到后台）
┌──────────┴──────────────────────────────▼──────────────────────────────────┐
│  core（与 UI 无关的可测业务层）                                             │
│  config · process_manager · sys_observer · log_parser · log_index · skill   │
└──────────┬──────────────────────────────┬──────────────────────────────────┘
           │ Arc 共享                      │
┌──────────▼─────────────┐   ┌─────────────▼────────────────────────────────┐
│ 后台 tokio 运行时       │   │ platform/（平台差异收口）                     │
│ axum HTTP+WS · 命令执行 │   │ browser · commands · signals                 │
│ MCP stdio/http · 采集   │   │                                              │
└────────────────────────┘   └──────────────────────────────────────────────┘
```

## 2. 线程与运行时模型

| 线程 | 职责 | 通信 |
|---|---|---|
| UI 线程（主线程） | windui 事件循环、Signal 写入、页面构建 | `App::channel` 收后台消息；闭包直接 `rt.spawn` |
| tokio worker ×2 | axum 服务器、`tokio::process` 命令执行、MCP | 共享 `Arc<AppState>` |
| sysinfo 采集线程 | 每 refresh_secs 刷新进程表/资源，产出快照 | `Sender<UiMsg>` → UI 线程；`broadcast` → WS |

关键约束（来自 windui 实测）：

- `Signal<T>` 是 `!Send`，只能 UI 线程写。后台一律发消息，由 `channel` 回调入 UI 线程写信号；因此 `UiCtx`（含 Signal）永不进后台任务——后台闭包只携带 `SharedState`/`Handle`/`Sender`。
- `on_interval` 回调在 UI 线程执行：只做「读快照 + 写信号」（微秒级）；sysinfo 采集在独立线程，绝不阻塞事件循环（NFR-PERF-01）。定时器语义为「改了东西才出帧」，看门狗式轮询不破坏空闲零 CPU。
- 命令执行（start/stop/check/install）经 `RuntimeHandle::spawn` 进 tokio；UI 永不等待。

## 3. 数据模型

### 3.1 配置（TOML，`directories` 定位）

```
~/.config/cucumber/config.toml        （macOS: ~/Library/Application Support；Windows: %APPDATA%）
  [general] refresh_secs=3  http_port=0  ws_port=0  auth_token=…  skill_dir=…  log_page_size=100
  [[process]]  # 进程条目数组
    id / name / type(generic|web_service|other)
    start_command / stop_command / check_command / install_deps_command
    start_detached=false  work_dir  env {k="v"}
    observe_name   # 系统进程模式：按进程名观察，不配置命令
    [[process.address]] protocol/host/port/path   # web_service 专用
    [[process.log_source]] name/path/command/encoding/format
```

- 命令以字符串配置，执行时按 shell 语义切分为参数数组（NFR-SEC-02：默认不穿 shell；需要管道时用户显式写 `sh -c "…"`）。
- `auth_token` 首次启动生成并持久化；任何日志输出与脱敏展示（`masked_token`）中不出现完整令牌（NFR-SEC-01）。
- 端口配置为 `0` 表示让系统分配，实际端口绑定后回写配置并持久化（FR-API-01）。

### 3.2 进程状态机（process_manager）

```
Stopped ──start()──▶ Starting ──spawn ok──▶ Running ─┬─stop()─▶ Stopping ──▶ Stopped
   ▲                                                        └─异常退出──▶ Error
   └──────────── 系统进程模式：由采集线程的 PID 观察直接映射 Running/Stopped
```

- `start_command` **spawn 语义**（默认）：长驻子进程，记录 PID，stdout/stderr 泵入 64KB 环形缓冲；子进程退出即转 Stopped(0)/Error(非 0)。
- `start_detached=true`：**点火即走**（等待命令退出，码 0 → Running），适配 `systemctl start` 类命令（ADR-03）。
- 停止优先级：`stop_command`（wait，码 0 = 成功）→ 本工具子进程 SIGTERM → 5s 轮询宽限 → SIGKILL（ADR-04，R-05）；Windows 用 `taskkill`（无 SIGTERM 对等物）。
- `check_command`：wait，退出码 0 = 健康，结果写入 `health`。
- 命令输出（stdout/stderr/退出码）保留最近一次，UI（列表资源列）与 API（`get_process`）均可查（FR-PROC-06）。

### 3.3 日志管线（log_parser + log_index）

```
文件 或 读取命令 ─▶ 行字节偏移索引(Vec<u64>) ─▶ 按页 seek+read ─▶ 解析 LogLine ─▶ 过滤 ─▶ 高亮区间 ─▶ RichDoc → rich 控件
```

- `LogLine { raw, level, tags, ts, message }`；格式预设：`json_lines`、`logfmt`、`bracket`（`[LEVEL] [TAG] ts msg`）、`plain`（整词级别嗅探）。
- 大文件不整读：缓存行偏移（10 万行 ≈ 0.8MB），过滤流式扫描只保留命中行号，取页时再 seek 读原始行（NFR-PERF-02/03）。
- 高亮在数据层预计算字符区间：级别→前景色、命中关键词→黄底，构造 RichDoc span 交 `Element::rich` 渲染（R-02 第一步：行级着色 + 单关键词）。
- 分页 50–1000 行/页，默认 100；跟随模式：每刷新周期全量重查并跳到最新一页（近似 tail -f）。

### 3.4 服务列表（services）

v1 数据源 = 运行中的 `web_service` 配置进程的地址展开（FR-SERV-01 第一类）；netstat 扫描增强项留待后续版本。

## 4. 对外接口（api/）

| 端点 | 说明 |
|---|---|
| `GET /api/health` | 免认证；版本、平台 |
| `GET/POST/PUT/DELETE /api/processes[/{id}]` | CRUD |
| `POST /api/processes/{id}/(start\|stop\|check\|install_deps)` | 操作 |
| `GET /api/dashboard` | 统计 + 资源指标 |
| `GET /api/services` | 服务列表 |
| `GET /api/logs/{id}?source&page&page_size&level&q&tag&ts_from&ts_to` | 日志查询 |
| `POST /api/skills/install` | skill 安装 |
| `GET /ws`（独立端口） | WebSocket：周期 dashboard 快照 + 控制消息 |
| `POST /mcp` | MCP JSON-RPC（Streamable HTTP 简化型） |

认证：`Authorization: Bearer <token>` 或 `?token=`；WS 用 query 参数。仅绑 127.0.0.1（NFR-SEC-01）。

MCP 工具集（与 GUI 能力对等，FR-API-02）：`list_processes` / `get_process` / `start_process` / `stop_process` / `check_process` / `list_services` / `get_dashboard` / `query_logs` / `install_skill`。

## 6. ADR（关键决策记录）

**ADR-01 MCP 自实现 JSON-RPC 子集，不引 rust-mcp-sdk。** MCP 核心（initialize/tools/list/tools/call）协议面极小且稳定；自实现约 300 行零新增依赖，彻底规避 R-04 的 SDK 版本漂移，handler 层与 HTTP API 复用同一 `api::ops`，协议升级只影响 `api/mcp.rs` 单文件。

**ADR-02 不引 regex / chrono / reqwest / open 等 crate。** 日志格式预设用手写解析器（四种格式已覆盖 v1 需求）；时间处理用 `std::time` + 手写 RFC3339/epoch/`YYYY-MM-DD HH:MM:SS` 解析（Howard Hinnant civil 算法）；浏览器打开按平台收口到 `platform/browser.rs`；帮助页健康检查用 tokio TCP 手写最小 HTTP/1.0 请求。轻量优先（NFR-PERF-03，30MB 内存预算）。

**ADR-03 start_command 双语义。** spawn（默认，长驻子进程）+ `start_detached`（点火即走），覆盖「直接跑二进制」与「systemctl 类命令」两类真实场景；避免用进程名反查 PID 的脆弱启发式。

**ADR-04 停止三级降级。** stop_command → SIGTERM/宽限 5s → SIGKILL；Windows 用 `taskkill /T`（无 SIGTERM 对等物，R-05）。

**ADR-05 日志读取命令限量 5 万行**，防止 `journalctl --no-pager` 无限输出拖垮内存；文件源不限量（偏移索引按需读页）。

**ADR-06 sysinfo 采集独立线程 + `App::channel` 回投。** `on_interval` 只写信号；windui 空闲零 CPU 语义依赖「什么都不做的 tick 不出帧」。

**ADR-07 UI 适配层 `ui/kit.rs`。** 主题色、统计卡片、Markdown→RichDoc 转换等收口于此（NFR-MAINT-03）；windui API 变动影响面最小化。业务页面不直接出现 `Color::rgb` 字面量。

**ADR-08 编辑对话框的地址/日志源用紧凑多行文本。** `proto://host:port[/path]` 每行一条、日志源 `名称 | 路径 | 命令 | 格式`。结构化行内输入（每字段一个控件）在行删除/重建时会丢失输入中状态（windui keyed diff 语义），文本域规避该问题且天然支持批量粘贴。

## 6.5 0.3.0 增补决策

**ADR-09 仪表盘自绘 Widget。** windui 无仪表控件；`ui/gauge.rs` 以 `Canvas` 原语（弧线段+圆帽、中心文字）实现圆环仪表，绑定 `Signal` 经 `Element::reactive()` + `on_update` 版本比对触发重绘。GPU 因 sysinfo 无传感器接口，以说明卡占位并帮助页注明（诚实边界）。

**ADR-10 轻量 i18n 自建字典。** 九语言 × ~90 键的静态表（`ui/i18n.rs`）；UI 文案持有 `Signal<String>`，`apply_lang` 统一重写信号即全站跟随。未用 windui `t!` 宏体系：现有文案为运行时中文串，自建字典可平滑迁移且语言切换即时生效。

**ADR-11 无回调控件经 UI 定时器桥接。** dropdown/slider 无选中回调（框架语义），语言与字号缩放经 1 秒 `on_interval` 比对信号差异后应用，避免重构为受控回调；代价是 ≤1 秒的生效延迟，可接受。

**ADR-12 更新检查零依赖。** GitHub Releases latest API + `curl` 子进程 + 手写 semver 比较；「跳过此版本」持久化于配置。不做自替换更新（运行中 exe/dmg 自替换跨平台复杂且危险），「立即更新」引导至下载页。

**ADR-13 托盘统计经 tooltip/菜单信号呈现。** 托盘面板非标准能力；统计以菜单首项（Signal 文案，弹出时现取）+ tooltip 周期刷新表达，左键唤起主窗口。

## 7. 验证策略与结果（0.1.0）

- **单元/集成测试**：40 项，覆盖配置 TOML 往返、令牌生成稳定性、状态机全生命周期（真实 `sleep` 子进程 spawn/stop/点火即走/失败路径）、健康检查、系统观察、四种日志格式解析、时间戳变体、文件分页/过滤、命令源、GBK 拒绝、高亮区间、地址解析、日志源解析、skill frontmatter/校验/幂等安装/拒绝可执行、MCP initialize/tools/call/notification、HTTP CRUD/认证（401/200）/dashboard、命令切分/执行/环形缓冲、信号失败路径。
- **静态检查**：`cargo clippy --all-targets -- -D warnings` 零告警；`cargo fmt --check` 通过。
- **GUI 冒烟**：`xvfb-run cucumber --smoke-test N` 退出码 0（CI Linux 必跑；Windows/macOS 仅编译验证）。
- **运行时实测**：`--version`、`--mcp` stdio 全协议（initialize/tools/list/notification/tools/call）、HTTP health/dashboard（免认证 + 令牌认证 + 401 拒绝）、真实系统指标采集。
- **编译矩阵**：GitHub Actions 原生 runner（windows-latest / macos-14 ×2 / ubuntu-22.04），不用交叉编译（R-06）。

## 8. 已知边界与后续演进（v1）

- 系统级服务管理限定为「观察 + 尽力而为信号」（R-03）；systemctl/launchctl/SCM 全量管理走用户自配命令。后续可加 `platform/services.rs` 收口三个平台的原生服务控制。
- 日志编码 v1 仅 UTF-8（GBK 字段已预留）；跟随模式为周期全量重查，尾部增量索引（refresh_tail）留待需要时实现。
- 系统托盘：Windows/macOS 可用（windui Tray），Linux 无状态栏协议支持时静默降级；Wayland 原生后端下全局热键不可用（协议限制，UI 帮助页已说明）。
- 服务页的系统级端口扫描（netstat 增强）未实现，接口已按「配置进程地址展开」设计，可平滑扩展。
